# Musique — Spotify setup (Transfert HQ)

Native **Musique** tab (admin session). Separate from local **Lecteur**.

## Spotify Developer Dashboard

1. Create an app at [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. Add a **Redirect URI** that matches HQ exactly, for example:
   - Local: `http://127.0.0.1:8765/api/spotify/callback`
   - Tailscale Serve HTTPS: `https://<your-host>/api/spotify/callback`
3. Note: after 2025-11-27, Spotify rejects bare `localhost` aliases and non-HTTPS remote redirects. `http://127.0.0.1` remains valid for local development.
4. Development-mode apps are limited to allowlisted Spotify users until extended quota / review.

## Scopes requested

`user-read-playback-state`, `user-modify-playback-state`, `user-read-currently-playing`, playlist read/modify (public+private+collaborative), `user-read-email`, `user-read-private`, `user-read-recently-played`, `user-library-read`, `user-top-read`.

The new tools use scopes already requested by HQ. If an older grant lacks a required scope, reconnect Spotify in Lecture. The optional `followed_artists` helper requires `user-follow-read`, which HQ does not request or use.

## API limitations (do not invent workarounds)

- Playback control requires a **Premium** account and an available Connect device.
- HQ can detect / wake **Spotify Desktop on this PC** and prefer that Connect target. It cannot route playback to raw Windows audio endpoints (WASAPI/DirectSound headphones/speakers) — only Spotify Connect receivers.
- Cover art is served via same-origin `/api/spotify/image?url=` (CSP blocks direct `i.scdn.co` / Spotify CDN loads).
- Public API queue: read + append only — no free reorder/remove.
- Observed 2026-11-12 on the owner's account: `PUT /me/player/play` with `uris` returns success but playback never starts (even one track), while a playlist `context_uri` plays. HQ therefore loads any track list into a private playlist **Musica · Lecture** (`.hq-music/playback_playlist.json`, recreated if deleted) and plays it with `offset 0` (+ `position_ms`). Every « Lire » on tracks, Mixer sessions, the quiz and DJ Musica go through it; DJ segments are appended to it so the show flows on. `direct_uris: true` keeps the raw call for testing.
- `/v1/recommendations` and `/v1/audio-features` are unavailable for new apps (Nov 2024). The Mixer uses weighted playlist pools instead.
- Spotify's [February 2026 Development Mode migration guide](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide) confirms a maximum of 10 results per search request. Use offsets for additional pages. Browse new releases and artist top tracks were removed. Playlist contents are limited to playlists the current user owns or collaborates on. Playlist mutations use `/playlists/{id}/items` and library checks use `/me/library/contains`. Profile product and popularity fields may be absent.
- The [Spotify Search reference](https://developer.spotify.com/documentation/web-api/reference/search) documents `artist:` and `year:` for albums and tracks, `genre:` for artists and tracks, and `tag:new` and `tag:hipster` for albums. The latter filters target releases from the past two weeks and low-popularity albums, respectively. Spotify can return sparse or empty results for a particular query or market.
- Playback, catalog, library and account permissions vary by grant, quota mode and market. The HTTP layer reports unavailable Spotify functions with `spotify_unavailable_endpoint`. Playback separately reports Premium requirements and missing Connect devices.
- Spotify's [recently played endpoint](https://developer.spotify.com/documentation/web-api/reference/get-recently-played) returns a limited history. Musica can report an observed play date. Absence from a recent sample is insufficient evidence for a three-month claim.

## Musica data sharing

Musica sends short conversation references and minimal catalog metadata to the AI provider. OAuth tokens, account identifiers, machine details, Spotify URIs and cover URLs stay server-side or in the authenticated HQ UI as appropriate. Listening history requires **Partager l'historique d'écoute avec Musica**, enabled by default and stored server-side. The Gemini key uses the free tier. Google may use submitted content and replies to improve its products and may use human reviewers. See [Gemini API terms](https://ai.google.dev/gemini-api/terms) and [Spotify's restrictions on machine learning use](https://developer.spotify.com/documentation/web-api/reference/search).

## Mixer

`hq_music_mixer.py` generates explainable sessions from playlist tracks + weights + repetition rules, then optionally saves a Spotify playlist and starts playback.

Browser-local bans migrate to the shared taste store after a successful response. Dismissals mark a discovery as seen. Disliking a track reduces its Mixer weight and three distinct disliked tracks from an artist trigger an automatic exclusion, which can be undone from Mixer.

## Radar and exploration

`hq_music_radar.py` searches releases from up to 25 favorite or top artists. It checks candidates against Spotify's library and the seen list. Musique refreshes the radar on open at most once a day. The manual Actualiser button can run it on demand, with both paths honoring Spotify's Retry-After window. Playlist co-occurrence uses only readable samples containing the seed artist. When Development Mode blocks public playlist contents, discovery falls back to genre searches and albums found with `tag:hipster`. Exploration creates a private Spotify playlist and the user can later save liked titles to Musica · Gardés.

## Salon extras

- **Journal d'écoute**: the bridge background tick reads `/me/player/recently-played` every 20 minutes and stores plays newer than the cursor, so the history outlives Spotify's 50-play window. Monthly recap (top artists and titles, streaks, weekday × hour heatmap, new artists with first-heard dates) in the **Journal** tab. Local only; Musica reads it through `my_listening_journal` only when history sharing is on.
- **Alertes de sorties**: opt-in in Découvertes. The radar then runs once a day even with Musique closed, and each new release is announced once.
- **DJ Musica**: per-device setting (Lecture › DJ Musica). On a track change, every N tracks, Musica speaks one line over the music with the existing voice route and ducking. Runs while Musique is open in the browser.
- **Minuteur de sommeil**: browser-side; fades the Connect device volume over the last minute, pauses, then restores the volume.
- **Teinte de pochette**: the cover comes through the same-origin proxy, so a canvas samples it to tint the dock and the now-playing card.
- **Quiz Musica**: blind test from saved tracks, tops or an owned playlist; the round plays from a random point and the dock masks the title until the answer.
- **Swipe**: discovery tracks play through Connect; right = like, left = dislike (three dislikes on one artist still auto-exclude it), up = not now.
- **Page artiste**: discography timeline from `artists/{id}/albums`, radar badges, journal stats, play the artist context.
- **Courbe d'énergie**: Spotify removed audio-features, so energy is the label the Master puts on each Mixer source.
- **Humeur du calendrier**: Mixer card built from today's manual calendar events (titles stay local).
- **Studio**: ACE-Step 1.5 turbo supports `repaint` (redo a passage), `cover` (restyle) and outpainting past the end (extend); `lego`, `extract` and `complete` need the base model, which is not installed. Variants use `batch_size` 2–3 with distinct seeds (duration × variants ≤ 240 s on the 8 GB GPU). The ACE-Step worker already exits after each job, so there is no resident process to auto-stop.

## DJ Musica — l'émission

`hq_music_dj.py`. A show is a chain of segments (4–6 tracks; a focus block fills its minutes). Candidates come only from evidence pools: radar releases (« en première » first), journal anniversaries (first heard a year ago), « on repeat » this week, forgotten favourites (≥ 3 plays, nothing for 90 days), verified discoveries and Spotify tops. History pools are used only with history sharing on. One model call picks the tracks by handle, names the segment and writes every line; the talk budget (discret / normal / bavarde) sets how many lines. Without a model, a plain fallback segment still plays.

- Voice first: a new segment (start, steering, « Segment suivant », autoplay rescue) fades the current music down and pauses it, her intro plays, then the browser calls `POST /api/musica/dj/go` and the segment's music starts (the PC station plays the intro and starts the music itself; a fallback starts it after the intro length + 10 s if nobody does). When the playlist flows naturally into the next segment, the driver pauses, plays her intro, then restarts the song from 0:00. Lines between tracks stay over the music, ducked. Other smoothing: shuffle and repeat are turned off; ducking under her voice ramps in 3–4 steps; the browser and the PC station look at the player again just after each track should end, so lines land on the change.
- Drops: Phonon voice, optional ident jingle in front and a quiet bed under the voice, mixed once by ffmpeg into `.hq-music/dj-cache/` (240 newest kept). They are built in the background while the music plays, so a line is ready when its track starts.
- Continuity: one segment is always ready ahead. As soon as a segment starts (or is promoted), the next one is planned and appended to the playback playlist, so « suivant » always lands on her picks; its intro plays when any of its tracks begins. If the queue still runs past her picks (Spotify autoplay), the show jumps back to the next segment instead of going off air; it steps aside only when the Master picked another context or replaced the playback playlist (`hq_spotify.playback_generation`). « Segment suivant » (`POST /api/musica/dj/next`) jumps to the next segment's playlist position, at once or as soon as it is ready; that jump is not counted as a skip.
- Steering: chips, free text or push-to-talk « DJ, … » in Musica replan at once. A skip within 30 s of a DJ pick counts as « not now »; a second quick skip of the same track counts as a dislike.
- Guests: on request or rarely (setting), Transferania or Else says one line in her own voice after the intro; the line is noted in her own memory store (`hq_companion_memory.memory_scope`), never in Musica's.
- Jingles: three ACE-Step instrumentals (ident 10 s, transition 10 s, bed 30 s) generated one at a time when the GPU is idle or on « Créer l'habillage ». They are hidden from Studio › Créations.
- Shows: matinale (chosen days and time) and Sunday recap (time) are scheduled by the bridge tick; with the PC station on they start on the PC, otherwise HQ notifies and Lecture shows « Lancer ». Calendar titles never go to the model (counts and times only).
- Learning: `taste_profile()` rebuilds local affinities before each plan — journal play counts (log-weighted), explicit likes (+3) and dislikes (−3), tracks of DJ picks played to the end (+0.6, a light like; three completions of one track become a real like), quick skips (−1.2), which pools get finished or skipped, what is played per part of the day (last 60 days) and recent steering requests. Candidates from loved artists move up and carry `aime: true`; a short brief « Goûts appris » goes into the planning call only with history sharing on. « Ce que j'ai appris » in the DJ card shows it; `POST /api/musica/dj/learned/reset` forgets the show's own signals (not the journal, likes or bans).
- Voice engine: « Moteur » = auto (default: Chatterbox when its daemon is ready, Phonon meanwhile), Chatterbox or Phonon. Chatterbox (`hq_voice_chatterbox.py`, `scripts/chatterbox_daemon.py`, venv `C:\AI\Chatterbox`, port 8059, GPU, English only) clones Musica from `C:\AI\Chatterboxoices\musica.wav`, a ~15 s clip recorded from her own Phonon voice (« Recloner sa voix »). The planner gives each line a mood (neutral, warm, hype, playful, tender, mysterious) mapped to Chatterbox's exaggeration / cfg_weight / temperature, and writes for speech. Guests and French stay on Phonon; any Chatterbox failure falls back to Phonon. Engine lists « Chatterbox TTS » with idle auto-stop (15 min default). Output carries Resemble's inaudible Perth watermark. Lines can switch mood mid-way with inline tags (« [tender] »): each mood part is recorded separately (split only at tags; long parts at sentences), joined with a 0.22 s breath, then mastered like Phonon (highpass 60 Hz, loudnorm −19 LUFS, 48 kHz). « Expressivité » (0.6–1.5, default 1.4 « Très vive ») scales exaggeration up and cfg_weight down; temperature stays ≤ 0.8 (higher caused crackle). The daemon analyses the reference clip once and keeps it loaded. Measured on the RTX 4060: ~16 s for a typical line, ~29 s for a long line with three moods; segment lines are prepared in the background, only the first intro of a show is waited for. « Comparer les voix » records the same line with both engines (`POST /api/musica/dj/voice-compare`).
- La Fouille (`hq_music_dj_dig.py`, called through `candidate_pools`): 16 sources in parallel under one 20 s deadline (a late or failing source is dropped, never awaited). Journal: this week's loops, anniversaries, forgotten favourites, same month last year, habits (this weekday ±1 h over 60 days); HQ likes. Spotify each time: short-term top, radar/premières, discoveries. Spotify cached in `.hq-music/dj-dig-cache.json` (6–12 h, raw rows, journal filters applied at use time, failures never cached): classics (6-month and all-time top not played for 60 days), liked tracks played at most once, unplayed tracks of saved albums, older albums of top artists, latest release of followed artists (all-time top artists where `/me/following` is closed) not played for 30 days, the Master's own playlists. A free-text request (or « Découvertes » / « Change ») gets 2–4 Gemini-written Spotify searches (validated, `search` pool). The request's focus (nostalgie, découvertes, nouveautés, change) reweights sources; each source's finish/skip record is Thompson-sampled; candidates are interleaved by weighted round-robin (premières first, ≤ 2 per artist, affinity order inside a source); tracks aired in the last 4 days rest (`state.aired`) unless fewer than 12 candidates remain. The prep bar shows what was found; each segment keeps `dig` (found, offered, focus, searches) and each track its `pool`, shown on the DJ card. Dev Mode note: `/artists/{id}/albums` rejects `limit` > 10 (`hq_spotify.artist_albums` uses 10).
- Web dig (`web` pool, `hq_music_dj_dig.web_finds` / `verify_on_spotify`): for a free-text request, one grounded Gemini search (`hq_ai.generate(search=True)`, 30 a day, `.hq-music/dj-web-dig.json`) lists 15–24 real tracks with the site each came from; each is accepted only after an exact Spotify lookup whose artist and title match (whole-word title rule). Fewer than 5 verified finds -> the Spotify-native searches run too. The web dig gets 15 s more than the 20 s deadline. Web search quota exists only on Gemini 2.x/2.5 (AI Studio « Ancrage de recherche »: 1.5K a day; « Gemini 3 and newer »: 0), so grounded calls use `hq_ai.SEARCH_CHAIN` (2.5 Flash Lite, then 2.5 Flash), never the 3.x chains. A reply counts as searched when it lists search queries (Flash Lite often omits source links). A « site » that is not a domain becomes the grounding source or « le web »; a find that is an album name stands in with that album's first track, verified the same way (live check: 23 of 24 finds verified). The fact pass maps answers by order when the model renames the keys. A search refusal pauses only search on that key/model for 10 min (`<slot>#search`), never the model's normal use.
- Default direction: setting « Musique par défaut » (`direction`, default `energie` = « Plus d’énergie », or another steer preset, or `aucune`). The planner gets it for « dj » segments when the Master hasn't steered; a typed request or a steer chip replaces it for that segment.
- Charme (setting `charm`: `complice` default | `charmeuse` | `seduisante`): how flirty she is on air. `charm_rule()` adds the register to the segment planner (not Focus), the weekly recap script and the one-liners (`hq_musica.dj_line`). « Séduisante » needs HQ's adult gate twice: saving it requires a request that passes `hq_ai.nsfw_allowed` (the Musica route passes `adult_ok`, else 403 `adult_required`), and `charm_level()` drops it to « charmeuse » whenever adult mode is off. Suggestive, never explicit, on air. The floating chip's remarks (`ambient_line`) keep their per-device adult tone; without it they follow the setting, capped at « charmeuse ». `public_state().charm` = `{level, adult}`.
- Musica's picks (setting `picks`, on by default; never in Focus): the planner names one of the segment's tracks `musica_pick` — a track she defends, preferably a discovery, forgotten or new one, never the opener (moved to second if needed) — and its line presents it as her bet. Played to the end = won, skipped in the first 30 s = lost, scored once (`pick_result`) in `record_completion` / `record_skip`. State `picks`: wins, losses, streak (> 0 wins in a row, < 0 losses), last 30 bets, per-artist record. The planner gets her record (`_picks_brief`: score, streak, last bets, artists that land or miss) so she can brag, tease herself and adjust. The DJ card shows the ★ badge and « Les paris de Musica » scoreboard; « Réinitialiser ce que j’ai appris » clears it.
- Web-checked facts (`hq_music_dj_facts.py`, setting « Anecdotes vérifiées », `facts`, on by default): before her lines are recorded (`_prepare_drops`), one Gemini call with Google Search (`hq_ai.generate(search=True)`, Gemma models skipped) rewrites each track line — and the intro of a segment she prepares ahead, while it is not recorded yet — around one true fact. Only `confident` rewrites from a reply that really searched (grounding sources present) are kept; otherwise her line stays. Once per segment (`facts_checked`), never for Focus, at most 40 searches a day (`.hq-music/dj-facts.json`). The DJ card marks checked lines (✓ + the fact) and lists the web sources.
- Rembobiner (`hq_music_dj_archive.py`, `.hq-music/dj-archive.json`, 30 episodes, 16 segments each): every aired segment joins the episode of the current run (a steer or duel continues it; « Rendre l'antenne » then a new start opens another). Drops are kept alongside the lines, so the DJ cache prune spares them; « Rejouer cette émission » (`POST /api/musica/dj/archive/replay`) airs the segments in order with their own lines, re-recording any drop the cache lost, then the show carries on live. A replay is not archived again, does not re-score her bets, and her sister guest does not repeat (her line was already noted in her own memory).
- Le Duel (`start_duel` / `vote_duel` in `hq_music_dj.py`): two verified tracks, an old favourite (forgotten, classics, anniversaries, tops…) against a novelty (radar, discoveries, web finds…); with a champion, the champion against an alternating challenger. One model call writes the announcement, the challenger's line and her forecast (hidden until the vote); without a model a plain duel airs. The vote (button or « DJ, le premier / le deuxième ») likes the winner, scores her forecast (`duels.right` / `wrong`), crowns the winner and counts defenses; at 3 defenses a champion retires to the Panthéon. A duel never counts as a skip or a bet.
- Le Tournoi (`start_tournament` / `next_tournament_match`): a bracket of 8 (4 when fewer are found) video game songs, one duel per match (quarts → demi-finales → finale), voted like Le Duel. The field is never from the model's memory: one grounded web search for critics' « best video game music » lists and iconic OSTs (`hq_music_dj_dig.request_pools`, same 30-a-day web budget), every title checked on Spotify with an exact artist + title match, Spotify-native search as backup, at most two tracks per composer, banned artists skipped. Fewer than 4 verified songs: `dj_not_enough`. She announces each match from the facts on hand and forecasts a winner (scored with the duel forecasts); the final winner is liked. It lives in the **Quiz** tab (« Lancer un tournoi jeux vidéo », then « Match suivant »; « DJ, un tournoi » also works), never as an unprompted offer. Her commentary: each match intro gives a personal, teasing remark on both songs and a forecast, the challenger's line reacts to the first song just heard, and every vote gets a spoken reaction (`vote_duel` → `_vote_reaction`: one model call from the choice, what he passed on, his recent choices and her forecast record; scripted line if the model is down). Over HTTP the verdict is instant: the route calls `vote_duel(choice, defer=True)`, which returns the scripted line immediately and writes the model line in the background (`_stream_reaction`, read through `GET /api/musica/dj/duel/reaction/<id>`); the page shows the verdict at once and speaks only the final line. Freshness: the bracket remembers the last 200 songs it offered (`tournament_seen`, matched on normalized title + lead artist, so another edition or uri of the same song counts), and they are not offered again while there are enough new ones; if not, repeats fill the gap and the card says how many. Each tournament uses a different **angle** (`GAME_ANGLES`: 8/16-bit era, JRPG, action and bosses, indie, recent, racing/sport, mood/horror, towns/menus/endings, fighting/platformers, strategy/open worlds; never one of the last three) both in the web search wording and in the Spotify backup keywords, and the web search is told which recent titles to skip. When the web is unavailable or short (budget, no search), the Spotify backup (`_game_search_pool`: angle keywords, covers/remixes/tributes filtered out, soundtrack-looking albums only) fills in and the card says so (`source`: web / mixed / spotify). **Seeding and upsets:** before the first match Musica ranks the 8 songs (one model call, else the artist he likes most) — that ranking is the seeding (1 = favourite, 1v8 / 4v5 / 2v7 / 3v6) — and keeps a separate secret pick. A lower seed beating a higher one is an **upset**: she can call it before the match (`underdog_call`) and reacts to it after. **Wild card:** if there was an upset and the option is on, after the semi-finals the biggest upset victim that is not a finalist comes back (« repêchage ») to challenge the lower-seeded finalist for a place in the final (one extra short match). **Blind matches** (default): the public state, the match cards and the bracket mask both songs as A/B (`masked`, names `?`, no uri) until the vote, the dock title is blurred client-side, her intro never names them (the model is not given the names), and the vote reaction reveals titles and composers — teasing him if he just eliminated one of his favourite artists. **Listening windows** (default): each song plays about 35 s (`WINDOW_SECONDS`) starting about a third into the track (`_window_start`; Spotify no longer provides audio analysis, so « best part » is a heuristic), A then B, then the music stops and the vote opens (`heard`); « Réécouter » replays one side (`POST /api/musica/dj/duel/listen`). A duel never plans a next segment, never scores skips and her line plays only while the vote is open. **Themes:** a random angle, a chosen one, or a free-text theme (`theme`, ≤ 80 chars); the bracket accepts `blind`, `window`, `wildcard`, `angle`, `theme`. **Hall of fame** (`hq_music_dj_hall.py`, `.hq-music/tournament-hall.json`, `GET /api/musica/dj/hall`): every bracket match feeds a per-song record (wins, losses, finals, titles), finals reached per artist (she mentions « 3rd final for this composer »), the champions list, the all-time ranking and the most-eliminated songs. **Rivalry:** her secret pick winning = a point for Musica, otherwise a point for him (streaks kept); the winner picks the next tournament's theme (he gets the chooser, or Musica picks and says so). **Cameo:** after the final, Transferania or Else says one line about the winner in her own voice (recorded in the background, stored in her own memory only). **Share card:** drawn client-side on a canvas (bracket, champion, her pick, rivalry) and saved or shared as a PNG. The same reaction applies to plain Duels. The card shows « Tour 1/3 · quarts de finale · match 2/4 » at every round (`round_no`, `rounds`). Before the first match she makes a secret pick for the whole tournament (`_predict_champion`: one model call from the entrants, else the artist he likes most); it stays hidden (`tournament.prediction` is null) until the end, when the winner's vote returns `result.final` and she comments the champion, his run, and either the gap with her pick (where it went out and who beat it) or that they chose the same.
- Recaps (`hq_music_wrapped.py`, Journal tab): **Ton récap** for a week, month or year (plays, hours, active days, longest streak, top artists and tracks, new artists with their first play, busiest weekday and hour, delta against the previous period; a share card is drawn client-side), **Ce jour-là** (what was played on today's date in earlier years, playable) and **Carte de tes goûts** (artists of the last 90 days linked when played within 25 minutes of each other, grouped by deterministic label propagation, drawn as an SVG with a text list underneath; « en sommeil » = well played in the 90 days before, nothing this month). Genres are not used: Spotify no longer reliably returns them in Dev Mode, so clusters come from listening behaviour only.
- Steering from anywhere in Musique: a **request line** under the tabs (`POST /api/musica/dj/steer`, works whether or not the show is on), an **on air strip** on every tab (segment, next, skip title / skip segment / sign off) and the **mood dial** (calm to hype, with a time budget: the planner gets the energy and the time left, the last segment is short and soft, nothing follows it and the show signs off). Focus blocks ignore the dial.
- Playback rough edges: a **recovery banner** when no device is active (reason: Spotify Desktop closed vs. open without an active device; one button wakes Desktop, picks the local Connect device and transfers playback); the **last known track** is kept in localStorage and shown greyed with an « injoignable » banner when Spotify cannot be reached. The queue view still shows what Spotify exposes: the public API cannot reorder or remove queued items, so there is no reorder.
- Tournament kinds: games (default), **decade** (a decade per edition, `year:` filter for the backup), **artists** and **albums** (a genre per edition, represented by the signature track), and **library** (his 8 most played songs of the last 90 days, one per artist, straight from the journal: no web, nothing repeated-guard). Each kind has its own hall of fame and rivalry file (`tournament-hall-<kind>.json`). **Défi du jour**: one express blind duel (20 s of each song) per day, streak of consecutive days (a missed day resets it), its own hall (`daily`), never touching the duel title.
- Accessibility of the arena, bracket and bubbles: groups and labels on the match, sides and bracket, `aria-current` on the current round, a polite live region announcing new matches, votes, reveals and Musica's bubbles, visible focus everywhere, decorative parts hidden, reduced-motion respected.
- Weekly audio recap (`hq_music_weekly.py`, Journal tab card, setting `weekly_audio`, on by default): Sunday from 10:00 (bridge tick through `hq_music_dj.tick`), once, when the last 7 days have at least 5 journal plays, HQ computes the week's numbers (plays, hours, active days, top artists/tracks, new artists, busiest day, night plays, previous week), Gemini writes an ~400-word script from those facts only (8–12 parts with moods; a plain template if the model is down), each part is recorded in her voice (Chatterbox, warmed up for up to 150 s, else Phonon) and ffmpeg mixes ident + parts + bed + transition into `.hq-music/dj-cache/weekly-<week>-<hash>.mp3` (8 weeks kept, `.hq-music/dj-weekly.json`). A notification says when it is ready; « Préparer maintenant » / « Refaire » run it on demand. Playing it pauses Spotify.
- Language: setting « Langue à l'antenne » = auto (default: English when Musica's saved Phonon voice is English-only, via `hq_voice_phonon.reply_language`), English or Français. It drives the planning prompt (title, intro, lines, guest line, joke), the fallback segment, the voice synthesis language, the « hors émission » one-liners and the quiz lines.
- Humour: setting jamais / parfois (every other segment, at most one joke) / souvent (one per segment). Light and affectionate, no invented facts; the joke is returned in `joke` and the last 12 are passed back so she does not repeat them. The « hors émission » one-liners follow the same setting.
- Browser driver: while a show is on air, a 10 s watcher keeps reading the player when Musique is hidden or another HQ view is open, so the last track still triggers the next segment. Sound: one shared audio element unlocked by the first tap (browsers block sound that starts on its own); if a drop is still blocked, the next tap plays it.
- PC station: a bridge thread polls the player every 5 s, drives the same `observe()`, lowers the Spotify volume and plays drops with `ffplay` on the PC speakers when the active device is this PC. While it runs, the browser shows the show but stays silent.

## Musica (steward chat)

Character companion for Musique (`docs/musica-persona.md`). Separate memory from Else / Transferania.

| Route | Role |
|-------|------|
| `GET /api/musica/status` | Persona + Spotify/profile snapshot |
| `GET /api/musica/thread` | Chat transcript |
| `GET /api/musica/taste` | Current taste and history-sharing preference |
| `POST /api/musica/taste` | Set `history_sharing` with a boolean |
| `POST /api/musica/chat` | Message → reply, actions, cards and thread. `context: "mixer_session"` explains the stored Mixer session |
| `POST /api/musica/clear` | Wipe Musica thread |
| `POST /api/musica/tool` | Direct tool invoke (debug) |
| `POST /api/musica/confirm` | Execute a destructive action using a one-time token |
| `POST /api/musica/speak` | Synthesize plain text locally and return a same-origin audio URL |
| `GET /api/music/taste`, `POST /api/music/taste` | Shared preferences, feedback exclusions, history sharing and seen markers |
| `GET /api/music/radar`, `POST /api/music/radar/run` | Read cached radar or refresh. `force: false` applies the once-per-day guard |
| `GET /api/spotify/albums/{id}` | Album metadata and track page |
| `GET /api/spotify/artists/{id}/albums` | Artist albums and singles |

All routes use an admin session. POST requests require CSRF protection.

**Code layout.** `hq_music_dj.py` keeps the show engine, the duel and the vote; the tournament (`start_tournament`, brackets, angles and kinds, repêchage, `_make_cameo`) and the daily challenge live in `hq_music_dj_tournament.py`, which reaches the shared state through `dj.` (so tests keep patching `hq_music_dj`) and is re-exported by `hq_music_dj`. The voice-daemon check inside `public_state` is cached 15 s (`voice_status_cached`). Keyboard: A / B (or 1 / 2, arrows) vote in an open match. The Quiz tab wears a dot while the daily challenge is unplayed. The taste map zooms (buttons, wheel, drag) and each artist opens their page.

**La station (programme, présence, mémoire).** `hq_music_station.py` + `.hq-music/station.json`. A weekly **grid** of up to 14 slots (`kind`: dj / matinale / focus / recap / duel / daily / tournament, `days`, `time`); the bridge tick (`hq_music_dj.tick` → `hq_music_station.tick`) airs the first due slot (45 min window, once a day) on the PC speakers when the station is on and a device is ready, otherwise notifies and keeps a « ready » entry the page can launch (`POST …/station/launch`, forgotten after 3 h). The morning show and the Sunday recap keep their switches in the DJ settings and are merged into the « coming up » list (`source: settings`); a suggested grid (daily 19:00, duel Friday 20:00, free show Saturday, tournament Sunday) is offered, never applied alone. **Précédemment sur Musica** is a plain sentence built from local data (episodes, duel champion, votes, last tournament, daily streak) since `seen`; « Compris » marks it read. **Mémoire:** `memory()` shows what she learned (artists she sees you play, those you tire of, day parts, finishes/skips, bans) with two safe corrections: stop proposing an artist (`ban`/`unban`) or reset what she learned on air. **Présence:** the Accueil card `musica` (key in `hq_home.KEYS`, placed after « Aujourd'hui » for older saved layouts) shows on air / next show / ready / daily streak / tournament and opens Musique on the right tab (one-shot `sessionStorage` hint `hq_music_tab`). `assets/hq-musica-moments.js` may show one short dismissible nudge outside the Musique tab: a ready show, the unplayed daily challenge after 17:00, a show starting within 15 min, or a focus suggestion after 90 minutes on a work view. Rules: one per kind per day, 45 minutes between two, never while the tab is hidden or on Musique, off with the DJ setting `moments` or « Plus de nudges »; any API error silences it for the session. The nudge is text only (the chip art is adult-mode art and stays on the Musique page).

**Talk back and live drops.** `hq_music_dj_talk.py` + `hq_music_dj_live.py`. *Talk back:* « DJ, … » and the request bar go through `POST /api/musica/dj/ask`. `classify` (plain rules on the first words, no model call, so a request is never slowed down) separates a **question** (« pourquoi cette chanson ? », « c'est quoi ce morceau », « who sings this? ») from a **request** (everything else, which steers as before; « quelque chose de calme » and « tu peux mettre du rock ? » are requests). A question gets one grounded model call from what the show knows about the track on air (`facts_now`: why she picked it, the line she said, the facts she checked, the pool) and she says so when she has nothing reliable (« de mémoire » for general artist details); with the model down a plain sentence from the same facts is used. The text appears at once (chip + line) and the voice is recorded in the background (`GET …/ask/<id>`), then played like any drop; if no expressive drop is possible the plain voice answers. A request returns an **acknowledgement** (« Reçu. Je prépare ça. ») with its voice already cached, said while the new segment prepares. A blind duel never answers with a title. *Live drops:* `observe` now returns `reaction` on an ordinary track change: a quick skip (`skip`), three quick skips in 6 minutes (`skips`), a skipped or finished bet (`pick_lost` / `pick_won`). Pacing (`state["live"]`): 150 s between reactions (75 s for a streak, 90 s for a bet), at least 2 tracks, a probability per event, no line repeated within 12, never on a segment start (her intro already speaks). The voice is prepared ahead: `warm` records the missing lines in the background (≤6 per run, at most every 10 minutes, one at a time, only while no segment or plan needs the voice, so it never queues in front of real work) and `react` prefers a line whose drop is already cached (`peek_drop`: never synthesizes, never wakes a daemon); when none is ready the text goes out alone and that line's voice is queued for next time, so a reaction never waits for a synthesis. With the voice worker online the lines are recorded on the other PC's GPU. `POST /api/musica/dj/live/warm` records them now.
